# سیستم مالی واحد اپ (سبک WHMCS) — یک پیاده‌سازی، بدون نسخه

هدف: یک سیستم مالی سراسری برای کل اپ (نه مخصوص ایران، نه مخصوص یک ورک‌اسپیس)، چندارزی، چند درگاه، با پنل سوپرادمین کامل و صفحه صورتحساب مشتری. تمام نام‌گذاری‌های «نسخه ۲» حذف می‌شوند و فقط «Billing» می‌ماند.

## ۱) پایه داده — بازنشانی و یکپارچه‌سازی

تمام داده مالی فعلی (فاکتور، پرداخت، کیف پول، دوره‌ها، اعتبار AI، jobها) پاک می‌شود و ساختار زیر جایگزین می‌گردد. هسته اثبات‌شده فاکتور/دوره/کیف پول حفظ می‌شود ولی سراسری و چندارزی می‌شود.

جدول‌های تنظیمات جدید:
- `billing_currencies` — ارزهای فعال، نماد، تعداد اعشار، ارز پایه
- `billing_exchange_rates` — نرخ تبدیل نسخه‌دار برای گزارش‌گیری
- `billing_gateways` — درگاه‌ها (زرین‌پال، کارت به کارت/دستی، Stripe و…)؛ فعال/غیرفعال، ارزهای مجاز، ترتیب نمایش، تنظیمات از پنل ادمین
- `billing_tax_rates` — نرخ‌های مالیات با دامنه کشور/جهانی
- `billing_coupons` + `billing_coupon_redemptions` — درصدی/مبلغی، سقف استفاده، انقضا، محدود به محصول
- `billing_products` + `billing_prices` — محصول (پلن یا آیتم مصرفی) و قیمت به ازای ارز و دوره (ماهانه/سالانه/یک‌بار)

جدول‌های موجود که یکپارچه می‌شوند:
- فاکتور، سطر فاکتور، پرداخت، تخصیص پرداخت، کیف پول، دوره اشتراک، سهمیه دوره‌ای، پیگیری بدهی — مبالغ از «ریال ثابت» به `amount_minor + currency` تبدیل می‌شوند
- حذف کامل جدول‌های نسخه‌بندی و rollout و ستون `billing_engine_version`؛ همه ورک‌اسپیس‌ها روی یک موتور

## ۲) موتور مالی (سرور، Express)

- صدور فاکتور: اشتراک (خرید/ارتقا/تمدید)، شارژ کیف پول، خرید اعتبار مصرفی، آیتم دستی ادمین
- محاسبه: جمع سطرها ← کوپن ← مالیات ← مبلغ نهایی به ارز فاکتور
- پرداخت: درگاه آنلاین، اعتبار حساب (کیف پول)، ثبت دستی توسط ادمین؛ فاکتور فقط با تراکنش موفق پرداخت‌شده می‌شود
- اثر فاکتور پرداخت‌شده دقیقاً یک بار اعمال می‌شود (کلید یکتا روی فاکتور): ساخت/تمدید دوره اشتراک، اعطای سهمیه AI، شارژ کیف پول
- ارتقا/تنزل با محاسبه تناسبی؛ تنزل در پایان دوره
- تمدید خودکار: فاکتور تمدید ← پرداخت خودکار از کیف پول ← فعال‌سازی دوره
- یادآوری، مهلت ارفاق و افت به پلن رایگان در صورت عدم پرداخت
- مصرف‌محور: اعتبار AI، پیامک و ذخیره‌سازی از یک رجیستری واحد «آیتم مصرفی» می‌آید و کسر مصرف به همان ترازها می‌خورد
- درگاه‌ها پشت یک interface واحد (`GatewayProvider`) با پیاده‌سازی زرین‌پال + پرداخت دستی/آفلاین + قلاب آماده برای Stripe

مسیرها: `/api/billing/*` برای مشتری و `/api/admin/billing/*` برای سوپرادمین. مسیرهای قدیمی legacy و V2 حذف می‌شوند.

## ۳) پنل سوپرادمین (سراسری)

بخش «مالی» با تب‌ها:
- داشبورد: درآمد، فاکتور معوق، MRR، مصرف
- محصولات و قیمت‌ها: تعریف پلن/محصول، قیمت هر ارز و هر دوره، ویژگی‌ها و محدودیت‌ها
- ارزها و نرخ تبدیل
- درگاه‌های پرداخت: فعال‌سازی و تنظیم
- مالیات و کوپن‌ها
- فاکتورها، پرداخت‌ها، کیف پول‌ها: جستجو، مشاهده، ثبت پرداخت دستی، صدور فاکتور دستی، ابطال، بازپرداخت
- مشتریان: پلن هر ورک‌اسپیس، تغییر پلن، اعطای اعتبار، تاریخچه
- حسابرسی: لاگ رویدادهای مالی

## ۴) صفحه مشتری

صفحه «صورتحساب» با: نمای کلی (پلن، دوره، اعتبار، بدهی)، پلن‌ها و ارتقا، فاکتورها و پرداخت، کیف پول و شارژ، اعتبار مصرفی (AI/پیامک/فضا)، تاریخچه تراکنش. کاملاً چندزبانه (fa/en/tr)، تاریخ شمسی برای فارسی، اسکلت لودینگ.

## ۵) پاک‌سازی

حذف `BillingV2Page`, `iran/*`, `billingV2Api`, `adminBillingV2`, سرویس‌های rollout/shadow/legacy و تست‌های مخصوص نسخه؛ جایگزینی با ماژول واحد `billing`.

## ترتیب اجرا

1. مهاجرت پایه: بازنشانی داده مالی + جدول‌های تنظیمات + چندارزی + حذف نسخه‌بندی
2. موتور سرور واحد + درگاه‌ها + workerها
3. API مشتری و ادمین
4. UI ادمین
5. UI مشتری + ترجمه‌ها
6. اجرای migrationها روی Supabase متصل، بیلد و تست

## نکات فنی

- مبالغ صحیح در واحد خرد (minor unit) با `BIGINT`؛ هیچ محاسبه پولی در کلاینت
- همه اثرهای مالی idempotent و پشت قفل
- کلید سرویس فقط سمت سرور؛ RLS + GRANT برای هر جدول جدید
- هیچ Edge Function جدیدی ساخته نمی‌شود؛ همه منطق در سرور Express
