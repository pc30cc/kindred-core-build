Web Yar for WHMCS — installation
================================

Requirements: WHMCS 8.0 or newer, PHP 7.2 or newer (as supported by your
WHMCS version), HTTPS on the WHMCS System URL.

1. Extract this archive into your WHMCS root directory. It creates
   modules/addons/webyar/ and nothing else.
2. WHMCS admin → System Settings → Addon Modules → "Web Yar" → Activate.
   Then "Configure" → Access Control: tick the admin roles that may manage it.
3. Addons → Web Yar:
   - Web/API addresses are preconfigured for app.webyar.ai / api.webyar.ai.
     Server operators can override WEBYAR_APP_URL / WEBYAR_API_URL in PHP;
   - click "Connect to Web Yar", choose the workspace, approve.
   - existing installations keep their previously saved URL as a fallback.
     URLs are displayed to administrators but cannot be changed in this page.
4. In Web Yar → Plugins → WHMCS, turn on the sections the assistant may read
   (services, domains, invoices, orders, tickets, announcements, knowledge
   base and network status). All except the public catalogue start OFF.
5. Super Admin -> Plugins -> WHMCS controls the overall plugin, AI access
   and each section for all workspaces. Disabled sections bypass even cache.
   After upgrading, click Check connection to refresh supported capabilities.
   The merchant name comes from WHMCS General Settings > Company Name.
   Click Check connection after changing that name to refresh it in Web Yar.

The widget is added to the client area automatically (can be switched off).
Customer data is never synced or polled in the background. Addon updates use cron.

Uninstall: Addon Modules → Web Yar → Deactivate. Only the addon's own
mod_webyar_* tables are removed. No WHMCS client, service, domain, invoice,
order or ticket data is touched. Then delete modules/addons/webyar/.

Full documentation: docs/commerce/WHMCS.md in the Web Yar repository, or the
guide linked from Web Yar → Plugins → WHMCS.

AUTOMATIC UPDATES (1.2.0+)
Install this release once to enable future automatic updates. Connected sites
check hourly via WHMCS CLI cron. Both the local Automatic updates checkbox and
Super Admin > Plugins > WHMCS > Automatic addon updates must permit updates.
Publish a higher addon version and deploy the app ZIP/JSON and API together.
Requires cURL, ZipArchive, tokenizer, a writable addon parent, and a private
working directory on the same filesystem. Set WEBYAR_UPDATE_DIR at server level
to a persistent directory outside the web root when the PHP temp directory is
on another filesystem. Run cron as the addon owner; keep web OPcache timestamp
validation enabled. Settings and credentials remain in place. The previous files
are retained in the private working directory for manual recovery. See
repository docs/commerce/WHMCS.md for recovery steps and deployment requirements.

Docker installations: bind a private host directory outside the WHMCS web root
to /var/lib/webyar-updates and set WEBYAR_UPDATE_DIR=/var/lib/webyar-updates
in the web/cron container. The host directory must be on the same filesystem
as the addon bind mount, owned by the cron user and have mode 0700. A /tmp
directory in the container overlay cannot stage updates for a host bind mount.
